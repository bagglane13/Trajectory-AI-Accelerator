# Техническое описание Trajectory AI 1.3.6

Локальное веб-приложение для подготовки к экзамену по программированию. Пользователь загружает методичку и контрольные вопросы, задаёт уровень и расписание. Приложение создаёт план, уроки, практику и итоговый тест с учётом ошибок. Обычный запуск выполняется через корневой START.bat.

## Технологии и компоненты

| Часть | Реализация | Задача |
| --- | --- | --- |
| Интерфейс | HTML, CSS, JavaScript | Страницы и формы, fetch к API, опрос статуса заданий |
| Сервер | Python, FastAPI, Uvicorn | Учётные записи, файлы, курсы и действия пользователя |
| Хранение | SQLite, SQLAlchemy | Курсы, источники, задания, попытки, прогресс и журнал |
| Нейросеть | Qwen3 4B, Ollama | Генерация материалов и оценка открытых ответов |
| Оркестрация | app/jobs.py | Очередь, этапы, проверка, исправления и сохранение |
| Работа с текстом | pypdf, python-docx, rank-bm25 | Извлечение текста и поиск подходящих фрагментов |
| Форматы ответов | Pydantic и JSON Schema | Проверка полей и допустимых ссылок |
| Защита | Argon2, сессии, CSRF | Хеширование паролей и проверка доступа |
| Установка | BAT, PowerShell, Python | Подготовка окружения и запуск на Windows |

Дополнительные адаптеры моделей в app/providers.py доступны при ручной настройке. Корневой START.bat всегда выбирает локальную Ollama. Основной сценарий не требует API-ключа или аккаунта у поставщика модели.

## Пользовательский сценарий

1. Зарегистрироваться в локальном приложении или войти в существующую учётную запись.
2. Создать курс: название, уровень, дата начала, срок, дни недели и минуты занятий.
3. Загрузить PDF с текстом, DOCX или TXT с методичкой; вопросы ввести по строкам или загрузить отдельным файлом.
4. Проверить извлечённые вопросы и учебный бюджет. При необходимости изменить уровень и расписание.
5. Запустить построение плана и дождаться результата в журнале AI.
6. Открыть тему, сгенерировать урок, изучить теорию, выполнить практику.
7. Завершить темы и пройти итоговый тест. Повторный запуск сохраняет курс и историю попыток.

Сроки: 15 дней, 1, 2, 3, 6 или 12 месяцев. Количество минут задаётся отдельно для выбранных дней недели. Даты рассчитываются по календарю, а не как условные недели.

## Документы и RAG

Загрузка выполняется через multipart/form-data с ограничением файла 20 МБ и извлечённого текста 1 000 000 символов. Исходные файлы хранятся в data/uploads, текст и фрагменты — в SQLite. Повторная загрузка одинакового документа определяется по хешу и роли документа.

PDF разбирается постранично, DOCX — по абзацам с учётом нумерации, TXT — как текст. Номер страницы не используется в качестве учебного ответа. Скан без текстового слоя отклоняется с пояснением о необходимости распознавания.

Поиск BM25 учитывает слова вопроса и темы. Оглавление, введение и страницы с плотным списком экзаменационных вопросов не должны подменять объяснение темы. Для плана выбираются опорные фрагменты по вопросам, для урока — расширенная выборка. Большая методичка не передаётся в каждом запросе целиком.

Модель получает только выбранные фрагменты, их идентификаторы, вопросы и параметры задания. В локальном запросе длинные идентификаторы заменяются короткими ссылками и затем восстанавливаются. JSON Schema ограничивает ссылки переданными источниками и вопросами. Сервер повторно проверяет их перед сохранением. Источники доступны пользователю для сверки.

## Генератор и проверяющий

CourseAgent и ReviewerAgent — две роли с разными системными инструкциями, использующие одну модель последовательно. Они не являются двумя отдельно обученными нейросетями. Программа управляет последовательностью вызовов; модель не запускает команды операционной системы и не записывает результаты напрямую в базу.

CourseAgent создаёт темы и цели плана; теорию, практику и ответы к вопросам урока; оценку открытого ответа; либо вопросы итогового теста. ReviewerAgent отдельным запросом проверяет содержание по источникам и условиям. При оценивании он проверяет справедливость балла, в том числе обоснованность низкой оценки.

## Очередь и ограниченный цикл

1. API сохраняет задание в состоянии queued. Для курса допускается одна активная AI-операция.
2. Фоновый поток выбирает старейшее задание. Атомарный claim переводит его в running и выдаёт токен исполнения; в базе хранится хеш токена.
3. Поиск формирует контекст и сохраняет запись search_materials.
4. Генератор возвращает JSON. Проверяются структура, источники, привязка к вопросам, содержательность заданий и календарная допустимость плана.
5. При структурной ошибке фиксируется программная проверка без лишнего запроса проверяющему. Иначе вызывается ReviewerAgent.
6. Замечания передаются генератору, пока номер версии меньше трёх. После одобрения выполняется повторная валидация и сохранение в транзакции.
7. После трёх неудачных версий результат остаётся неопубликованным. Пользователь получает причину и возможность повторить операцию.

Завершённые состояния: completed, needs_input, needs_review, failed, interrupted. Отмена и проверка версии курса препятствуют сохранению результата устаревшего задания. Heartbeat используется для обнаружения зависших задач: после 15 минут без обновления требуется повтор. Это ограничение этапа, а не точный прогноз длительности курса.

Idempotency-Key и проверка текущей операции предотвращают дубликаты. Токен исполнения используется внутри процесса. Во время долгого запроса к модели транзакция записи SQLite не удерживается.

## Расписание и уровень знаний

Календарный план размещает длительность тем по доступным дням и добавляет 25% времени на повторение. Занятие может быть разделено на несколько дат. Не помещающийся план отклоняется с просьбой изменить срок или нагрузку.

Предварительная оценка черновика использует 45, 30 или 20 минут на контрольный вопрос для уровней с нуля, знаком с основами, повторение. После генерации учитываются длительности оставшихся тем. Эти оценки приблизительны и не являются диагностикой знаний.

Изменение уровня и расписания сначала можно проверить через preview. Сохранение готового курса атомарно: при нехватке времени прежнее расписание остаётся. Завершённые уроки и попытки сохраняются; уже созданная теория автоматически не переписывается.

## Практика и прогресс

Тест с выбором варианта проверяется программно по сохранённому правильному ответу и получает 0 или 100 баллов. Открытый ответ анализируется моделью: сначала оценка, затем проверка этой оценки. До успешного завершения оценки балл не считается выставленным. Код из ответа не выполняется.

Тема завершается, когда теория отмечена прочитанной и все обязательные задания пройдены с результатом от 70%. Дополнительная практика не блокирует завершение. В демонстрационном режиме самопроверка обозначается отдельно и не выдаётся за AI-оценку. История попыток сохраняется, эталоны скрыты из публичных данных до разрешённого разбора.

## Итоговый тест

После завершения всех тем создаётся схема из 10 заданий. Если имеются темы с ошибками и без ошибок, семь заданий выделяются первым и три остальным. Если ошибались во всех темах, все задания относятся к этим темам. Учитываются и ошибки, позднее исправленные верным ответом.

Генератор создаёт вопросы по схеме, проверяющий контролирует результат. Проверка выбора выполняется программой. Попытки и разбор сохраняются отдельно от повседневной практики.

## Протоколы и адреса

| Соединение | Протокол | Данные |
| --- | --- | --- |
| Браузер → FastAPI | HTTP на 127.0.0.1 | JSON, cookie сессии, CSRF-заголовок |
| Загрузка документа | HTTP POST | multipart/form-data |
| FastAPI → Ollama | Локальный HTTP POST /api/chat | JSON, модель, инструкции, контекст, схема ответа |
| FastAPI → SQLite | Встроенный доступ к файлу | SQLAlchemy, транзакции, внешние ключи, WAL |
| Подготовка компонентов | HTTPS | Скачивание Python, библиотек, Ollama и модели |

Сайт выбирает свободный порт 8000–8019, приватный Ollama — 11435–11454. Фактические адреса выводятся запускатором. Отдельно установленный сервер на 11434 не перенастраивается. После установки локальный сценарий работает без интернета.

## Основные маршруты API

Актуальная схема формируется FastAPI по /docs и /openapi.json. Все пользовательские операции проверяют владельца курса и сессию.

| Курсы | GET/POST /api/courses, GET/DELETE /api/courses/{id} |

## Хранение и защита

Таблицы: users, sessions, courses, documents, chunks, lessons, attempts, jobs, agent_runs, final_exams, final_exam_attempts. Пользователь владеет курсом; документы, уроки, задачи и итоговые тесты связаны с курсом, попытки — с соответствующим заданием. Удаление курса каскадное, сначала требуется остановить активную операцию.

Пароли хешируются Argon2. В базе хранится хеш случайного токена сессии, cookie имеет HttpOnly и SameSite. Изменяющие запросы требуют CSRF-токен, проверяется Origin. Есть ограничение частоты попыток входа, заголовки CSP и проверка владения объектами.

Резервное копирование выполняется при остановленных серверах: сохраняется вся data с uploads и файлами базы. Локальные .env, .runtime, .venv и data исключены из Git и сборочного ZIP. Учебные примеры входят в архив, личные методички пользователя — нет.

## Установка и проверка

START.bat запускает START.ps1, который находит стабильный Python x64 или устанавливает его. run_local.py готовит окружение, проверяет зависимости, поднимает приватный Ollama и скачивает отсутствующую модель. Затем отправляет реальный короткий запрос со строгой схемой {"ok": true}. После двух неудачных попыток сайт не запускается, причина записывается в startup-ai.json.

При успешной проверке запускается один Uvicorn и открывается браузер. Исходники используются из соседней ai-accelerator. Повторный запуск использует уже скачанную модель. На новом компьютере нужны интернет для установки, Windows x64 и достаточные память и место.

Автоматические результаты и границы проверки описаны в ../TESTING.md. Проверка преподавателем — ../PREPOD_START_HERE.txt. Инструкции по обновлению — ../UPDATE_1_3_6_RU.txt.

## Ограничения качества

Модель и проверяющий могут ошибаться: особенно в полноте составного вопроса, однозначности вариантов теста и уместности рекомендаций. Источник следует сверять вручную. Приложение не распознаёт PDF-сканы и не исполняет код студента. Локальная генерация на процессоре может занимать несколько минут на запрос. Качество не гарантируется самим фактом успешного HTTP-ответа или одобрения ReviewerAgent.
